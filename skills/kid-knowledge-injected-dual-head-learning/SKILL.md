# KID: Knowledge-Injected Dual-Head Learning for Multimodal Content Classification

This skill enables Claude to design and implement knowledge-grounded multimodal classification systems based on the KID framework. KID solves the problem of implicit toxicity detection in memes (and similar multimodal content) by injecting entity-anchored external knowledge into a dual-head architecture that jointly optimizes semantic generation and discriminative classification. The core insight is that harmful content often depends on cultural/contextual knowledge absent from the image+text alone, and that decomposing classification into structured reasoning chains dramatically improves detection.

## When to Use

- When the user wants to build a harmful meme or hateful content detection system that goes beyond surface-level image+text features
- When classifying multimodal content that requires external world knowledge (cultural references, dog-whistles, coded symbols)
- When the user asks to implement a dual-head architecture combining generative reasoning with discriminative classification
- When building a content moderation pipeline that needs explainable reasoning chains alongside predictions
- When fine-tuning a vision-language model (e.g., Qwen2.5-VL, LLaVA) for binary or multi-label content classification
- When the user needs to handle multilingual harmful content detection across high- and low-resource languages

## Key Technique

**Entity-Anchored Knowledge Injection.** KID uses a teacher MLLM (e.g., Gemini-2.5-Flash) to generate interleaved augmented descriptions where each recognized entity is immediately followed by its background knowledge inline. For example, an image of Pepe the Frog becomes: `"The image shows <Pepe the Frog> [an internet meme symbol often used by far-right groups], looking at..."`. This inline format outperforms appended-glossary formats by 2.7-3.6% Macro-F1 because it preserves the contextual binding between entity and knowledge. Critically, the optimal knowledge quantity is N=2 entities per sample -- fewer leaves semantic gaps, more introduces noise that degrades the signal-to-noise ratio.

**Dual-Head Joint Learning.** Rather than using a single classification head or a single generative head, KID attaches two heads to a shared vision-language backbone: (1) a semantic generation head that autoregressively produces the target label in natural language (e.g., "This meme is harmful because it uses a hate symbol"), trained with causal language modeling loss; and (2) a discriminative classification head -- an MLP using last-token pooling -- trained with cross-entropy loss. The total loss is `L_total = L_gen + L_cls` with equal weighting. This forces the shared backbone to learn representations that support both explainable reasoning and crisp decision boundaries, which neither head alone achieves.

**Label-Constrained Distillation.** The reasoning chains generated by the teacher model are constrained to terminate at the ground-truth label. This prevents hallucinated rationales that sound plausible but lead to wrong classifications. The student model learns to reproduce these label-anchored chains, grounding its internal representations in factual reasoning paths rather than spurious correlations.

## Step-by-Step Workflow

1. **Define the classification task and label space.** Specify whether the task is binary (harmful/non-harmful), multi-class, or multi-label. Define exact label names that will anchor the reasoning chains (e.g., `["harmful", "non-harmful"]` or `["misogynistic", "shaming", "objectification", "violence"]`).

2. **Build the entity-anchored knowledge generation pipeline.** Use a capable MLLM (GPT-4o, Gemini, Claude) as the teacher to process each meme image+text. Prompt it to: (a) identify up to N=2 key entities in the meme, (b) generate inline knowledge descriptions in the format `<Entity> [background knowledge]`, and (c) produce the full interleaved augmented description `T_hat = {w1, ..., <Entity_j>, [Knowledge_j], ..., wm}`.

3. **Construct label-constrained reasoning chains.** For each training sample, prompt the teacher model with the image, text, knowledge description, AND the ground-truth label. Instruct it to produce a reasoning chain that connects visual evidence and background knowledge to the given label. This constraint ensures chains are factually grounded.

4. **Prepare the augmented training dataset.** Each sample becomes the tuple `(Image, Original_Text, Augmented_Description, Reasoning_Chain, Label)`. Store in a format compatible with your VLM training pipeline (JSON lines with image paths).

5. **Configure the dual-head model architecture.** Start from a vision-language backbone (Qwen2.5-VL-7B recommended). Attach: (a) the existing LM head as the semantic generation head, and (b) a new 2-layer MLP classification head that takes the last token's hidden state, applies dropout (0.1 input, 0.2 hidden), and projects to the label space via `softmax(ReLU(h @ W1 + b1) @ W2 + b2)`.

6. **Implement the joint training loop.** Compute both losses per batch: `L_gen` = negative log-likelihood over the reasoning chain tokens; `L_cls` = cross-entropy between MLP output and ground-truth label. Sum them with equal weight. Use QLoRA (INT4) for parameter-efficient fine-tuning with learning rate 2e-5 for the backbone and 1e-4 for the MLP head, batch size 16, max 4 epochs.

7. **Build the inference pipeline.** At inference time: (a) run the teacher MLLM to generate entity-anchored knowledge for the new meme, (b) feed `(Image, Text, Augmented_Description)` to the fine-tuned model, (c) collect both the generated reasoning chain from the semantic head AND the class probabilities from the classification head, (d) use the classification head's argmax as the final prediction and the reasoning chain as the explanation.

8. **Evaluate with appropriate metrics.** Use AUC and accuracy for binary tasks; Macro-F1 and accuracy for multi-class/multi-label tasks. Always report Macro-F1 for imbalanced datasets, which is common in harmful content detection.

9. **Tune knowledge quantity if performance plateaus.** If the model underperforms, experiment with N=1 to N=4 entities per sample. The relationship follows an inverted-U curve -- N=2 is typically optimal, but domain-specific content may shift the peak.

10. **Deploy with on-the-fly knowledge augmentation.** In production, the teacher model generates knowledge descriptions in real time before classification. Cache entity-knowledge mappings to reduce latency for frequently seen entities.

## Concrete Examples

**Example 1: Building a Harmful Meme Detector**

```
User: I want to build a system that detects harmful memes. Many memes
reference cultural symbols that make them hard to classify from pixels alone.

Approach:
1. Define binary labels: ["harmful", "non-harmful"]
2. Set up entity-anchored knowledge generation with a teacher model:

   Prompt template for knowledge generation:
   ---
   Analyze this meme image and its text: "{meme_text}"
   Identify the top 2 most significant entities (people, symbols, references).
   For each entity, provide brief background knowledge relevant to
   potential harmfulness.
   Format: Describe the image with inline annotations:
   "<Entity> [background knowledge]"
   ---

3. Generate label-constrained reasoning chains:

   Prompt template for chain generation:
   ---
   Meme text: "{meme_text}"
   Knowledge description: "{augmented_description}"
   Ground-truth label: {label}

   Write a 2-3 sentence reasoning chain that connects the visual
   evidence and background knowledge to the label. End with:
   "Therefore, this meme is {label}."
   ---

4. Fine-tune Qwen2.5-VL-7B with dual heads using QLoRA.

Output (at inference):
  Classification: harmful (confidence: 0.94)
  Reasoning: "The meme depicts <Pepe the Frog> [a symbol co-opted
  by extremist groups] overlaid with antisemitic text referencing
  <triple parentheses> [an antisemitic symbol used to identify
  Jewish individuals]. The combination of hate symbology with
  targeted rhetoric constitutes harmful content. Therefore, this
  meme is harmful."
```

**Example 2: Multi-Label Misogyny Detection**

```
User: I need to classify memes into multiple categories of misogyny:
shaming, stereotyping, objectification, and violence.

Approach:
1. Define multi-label space: ["shaming", "stereotype", "objectification",
   "violence"] with binary indicator per label.
2. Modify the classification head output to sigmoid (not softmax)
   with binary cross-entropy loss per label.
3. Generate knowledge descriptions focusing on gender-related entities
   and cultural references.
4. Reasoning chains address each applicable label:

   Example chain: "The meme shows a woman in a kitchen with text
   'where she belongs.' <Kitchen stereotype> [a longstanding
   misogynistic trope confining women to domestic roles]. The
   imagery reinforces <gender role stereotyping> [assigning fixed
   social roles based on gender]. Labels: stereotype=1, shaming=0,
   objectification=0, violence=0."

5. Training: L_total = L_gen + L_cls where L_cls uses
   binary cross-entropy across all 4 labels.

Output:
  Labels: {stereotype: 0.91, shaming: 0.12, objectification: 0.08,
           violence: 0.03}
  Reasoning: "The meme employs the domestic-role stereotype by
  depicting..."
```

**Example 3: Adapting KID to a New Domain (Product Review Fraud)**

```
User: Can I use this dual-head approach for detecting fake product reviews
that use subtle manipulation tactics?

Approach:
1. Reframe the knowledge injection: entities become brand names,
   product features, and known manipulation tactics.
2. Teacher model generates: "<BrandX> [a brand frequently targeted
   by astroturfing campaigns] ... <suspiciously specific praise>
   [a pattern common in incentivized reviews]"
3. Labels: ["authentic", "fraudulent"] or multi-label
   ["incentivized", "competitor_attack", "bot_generated"]
4. Dual-head architecture remains the same -- generation head
   produces reasoning, classification head produces prediction.
5. Key adaptation: replace the vision encoder pipeline with a
   text-only backbone if reviews lack images, or keep multimodal
   if reviews contain product photos.

Output:
  Classification: fraudulent (confidence: 0.87)
  Reasoning: "The review mentions <specific batch number B2847>
  [unusual specificity suggesting insider knowledge] and uses
  <superlative stacking> [three consecutive superlatives, a
  pattern 4x more common in incentivized reviews]. Therefore,
  this review is fraudulent."
```

## Best Practices

- **Do:** Use inline knowledge injection (entity immediately followed by its knowledge) rather than appending all knowledge at the end. The inline format preserves contextual binding and consistently outperforms appended formats.
- **Do:** Constrain reasoning chains to the ground-truth label during training. Unconstrained chains risk teaching the model plausible-sounding but factually wrong reasoning paths.
- **Do:** Keep knowledge quantity at N=2 entities per sample as a starting default. This is the empirically validated sweet spot across multiple datasets and languages.
- **Do:** Use separate learning rates for the backbone (2e-5) and the classification MLP head (1e-4). The MLP needs faster convergence since it starts from random initialization.
- **Avoid:** Using only the generative head or only the classification head. Ablation studies show the dual-head combination consistently outperforms either head alone by 2.5-5%.
- **Avoid:** Injecting knowledge about every detected entity. Beyond N=2, added knowledge introduces noise that degrades performance (the inverted-U effect). Be selective about which entities get knowledge annotations.

## Error Handling

- **Teacher model generates irrelevant knowledge:** Add a relevance filter that checks whether the generated knowledge relates to the image/text content. Discard or regenerate if cosine similarity between knowledge embedding and meme embedding falls below a threshold.
- **Reasoning chains hallucinate facts:** This is why label-constraining is essential. If chains still hallucinate, add a verification step where a second model checks factual claims in the chain against a knowledge base.
- **Classification and generation heads disagree:** At inference, always trust the classification head for the final label. Use the generation head's output only as an explanation. If disagreement rate exceeds 15%, the model may need more training epochs or the knowledge quality may be poor.
- **Low-resource language performance drops:** KID was validated on Bengali (low-resource). If performance is weak, increase training data through translation augmentation or use a multilingual backbone (e.g., Qwen2.5-VL supports 20+ languages).
- **MLP head loss dominates training:** If the classification loss is orders of magnitude larger than the generation loss in early epochs, add gradient clipping or normalize losses before summing.

## Limitations

- **Requires a capable teacher model.** The knowledge generation step depends on a strong MLLM (Gemini, GPT-4o, Claude) that can identify culturally relevant entities and produce accurate background knowledge. If the teacher model lacks knowledge about a specific cultural context, the pipeline inherits that blind spot.
- **Latency at inference.** On-the-fly knowledge generation adds a teacher-model call before each classification. For real-time moderation, entity-knowledge caching is necessary but won't cover novel entities.
- **Not suitable for purely visual harm.** KID excels at implicit, knowledge-dependent toxicity (dog-whistles, coded symbols). For explicit visual harm (graphic violence, nudity), standard vision classifiers may suffice and be faster.
- **Label-constrained chains can limit generalization.** By anchoring chains to specific labels, the model may struggle with out-of-distribution content that doesn't fit the predefined label taxonomy.
- **Dual-head architecture increases model complexity.** The added MLP head and joint loss require careful tuning. For simple binary tasks with abundant training data, a single classification head may perform comparably with less engineering overhead.
