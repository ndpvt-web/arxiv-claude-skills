# Abstention-Aware Reasoning: Teaching Systems When Not to Answer

This skill enables Claude to help build AI pipelines where models learn to **abstain** -- explicitly refuse to answer -- when evidence is insufficient, temporally contradictory, or ambiguous, rather than hallucinating a plausible-sounding wrong answer. The core technique, from "When Silence Is Golden" (ICLR 2026), frames abstention as a *teachable skill* trained via a two-stage pipeline: supervised fine-tuning (SFT) on Chain-of-Thought traces that include "No Answer" reasoning, followed by reinforcement learning (GRPO) with a custom reward function that jointly optimizes answer accuracy and honest abstention. A 1.5B model trained this way outperforms GPT-4o on temporal QA benchmarks.

## When to Use

- When the user is building a QA system that must handle **unanswerable questions** gracefully (e.g., contradictory evidence, missing temporal context, ambiguous queries)
- When implementing **temporal question answering** where facts change over time and the model must distinguish between time periods
- When designing a **reward function for RL fine-tuning** that needs to balance accuracy with honest uncertainty
- When the user wants to **reduce hallucination** by training or prompting a model to output "No Answer" instead of guessing
- When building **retrieval-augmented generation (RAG)** pipelines where retrieved context may be insufficient or contradictory
- When creating **evaluation frameworks** that measure not just accuracy but also abstention quality (true positive rate on unanswerable questions, false positive rate, calibration)
- When the user asks how to **filter temporal sub-contexts** from documents so only time-relevant facts reach the model

## Key Technique

**Abstention as a teachable skill, not a calibration trick.** Traditional approaches use output probability calibration (e.g., thresholding softmax confidence) to decide when a model is uncertain. This paper shows that calibration is unreliable for complex reasoning -- it doesn't capture true epistemic uncertainty. Instead, the method teaches the model to *reason its way to abstention* through explicit Chain-of-Thought steps. The model generates structured output in `<think>...</think><answer>...</answer>` format, where the thinking trace can conclude with a reasoned decision to output "No Answer."

**Two-stage training: SFT then GRPO with abstention-aware rewards.** Stage 1 collects high-quality CoT traces (generated by a strong teacher model like GPT-o1) that include both answerable and unanswerable examples, then fine-tunes the student model on these traces. Stage 2 applies Group Relative Policy Optimization (GRPO) with a custom reward function: `R = R_format + R_answer`, where `R_format = 0.5` if the output uses correct `<think>/<answer>` tags, and `R_answer` is: `1.0` for correctly abstaining on unanswerable questions, `ROUGE-L + Exact Match` for correct answers, and `0` for hallucinations or over-abstention. This reward structure makes "No Answer" a first-class output worth full credit when appropriate, eliminating the bias toward always attempting an answer.

**Why RL matters more than SFT alone.** The paper demonstrates that SFT induces overconfidence -- models learn surface patterns of reasoning without calibrated uncertainty. RL with abstention-aware rewards corrects this by exploring the answer/abstain boundary during training. The result: 20% higher true positive rate on unanswerable questions compared to SFT-only, while maintaining or improving accuracy on answerable ones.

## Step-by-Step Workflow

1. **Define the answerable/unanswerable boundary for your domain.** Establish clear criteria: what makes a question unanswerable? In temporal QA, it's contradictory or missing time-specific evidence. In RAG, it's insufficient retrieved context. In medical QA, it's ambiguous symptom descriptions. Write these criteria as annotation guidelines.

2. **Curate a training dataset with explicit unanswerable examples.** Ensure at least 20-30% of training questions are genuinely unanswerable with ground truth labels of "No Answer." For temporal datasets, include questions where the answer changed between time periods and the context only covers one period. Do not synthetically generate unanswerable questions by just removing context -- use naturally occurring ambiguity.

3. **Generate Chain-of-Thought traces that model abstention reasoning.** Use a strong teacher model (e.g., GPT-4o, Claude) to generate step-by-step reasoning for both answerable and unanswerable examples. For unanswerable cases, the CoT must explicitly reason through *why* the evidence is insufficient, not just output "No Answer." Filter traces -- only keep those where the final answer matches ground truth.

4. **Extract temporal sub-contexts (if applicable).** For time-sensitive domains, implement a temporal filtering step: given a question with timestamp t_q and a context passage, extract only the sentences relevant to that specific time period. This reduces noise from facts about other time periods that would confuse the model. Use a lightweight LLM call or rule-based date extraction.

5. **Format training data with structured output tags.** All training examples should follow: `<think>[reasoning steps]</think><answer>[answer or "No Answer"]</answer>`. This structured format enables the format reward component and makes abstention a discrete, parseable decision.

6. **Run SFT on the curated CoT dataset.** Fine-tune the base model on the full-parameter CoT dataset. Use standard hyperparameters (lr ~1e-5, weight decay ~1e-2). Train until convergence on a held-out validation set. This gives the model the *capability* to reason and abstain, but it will be overconfident.

7. **Implement the abstention-aware reward function for RL.** Code the two-component reward:
   - `R_format`: 0.5 if output contains valid `<think>` and `<answer>` tags, else 0.
   - `R_answer`: 1.0 if both prediction and ground truth are "No Answer"; ROUGE-L(pred, gold) + EM(pred, gold) for answerable questions where model answers; 0 for hallucinations (answering when should abstain) or over-abstention (abstaining when answer exists).

8. **Run GRPO reinforcement learning.** Apply Group Relative Policy Optimization: sample G=4 outputs per question, compute rewards, derive advantages relative to the group mean, and update the policy with clipped objective (epsilon=0.2) and KL penalty (beta=0.01) against the SFT checkpoint as reference. Train for 2-3 epochs.

9. **Evaluate with abstention-specific metrics.** Go beyond standard accuracy. Measure: True Positive rate (correctly abstaining on unanswerable), False Positive rate (incorrectly abstaining on answerable), False Negative rate (answering when should abstain), Exact Match, ROUGE-L, and BERTScore. Plot calibration curves to verify the RL model is better calibrated than SFT-only.

10. **Deploy with structured output parsing and fallback.** In production, parse the `<think>/<answer>` tags. When the model outputs "No Answer," surface this to the user with the reasoning trace as justification. Implement a fallback: if tags are malformed, treat the response as low-confidence and route to a human reviewer or secondary model.

## Concrete Examples

**Example 1: Building an abstention-aware temporal QA pipeline**

```
User: I have a dataset of news articles with timestamps and questions about
events. Some questions ask about time periods not covered in the articles.
I want my model to say "I don't know" instead of making up answers.

Approach:
1. Audit the dataset -- label questions as answerable or unanswerable based
   on whether the article covers the relevant time period.
2. For each question, extract temporal sub-context:
   - Parse the question's target timestamp (e.g., "Who was CEO in 2019?")
   - Filter article paragraphs to only those mentioning 2019 events
   - If no paragraphs match, mark as unanswerable
3. Generate CoT traces with a teacher model:
   Answerable: "<think>The question asks about the CEO in 2019. Paragraph 3
   states 'Jane Doe was appointed CEO in January 2019.' This directly answers
   the question.</think><answer>Jane Doe</answer>"
   Unanswerable: "<think>The question asks about the CEO in 2019. The article
   covers events from 2021-2023 only. No information about 2019 leadership
   is present.</think><answer>No Answer</answer>"
4. SFT on these traces, then GRPO with abstention-aware rewards.
5. Evaluate: target TP rate > 80% on unanswerable, EM > 70% on answerable.

Output (model in production):
  Question: "What was the company's revenue in Q3 2020?"
  Context: [article covering Q1-Q2 2020 and Q1 2021 only]
  Model: <think>The question asks about Q3 2020 revenue. The provided context
  covers Q1 2020 ($4.2M), Q2 2020 ($4.8M), and Q1 2021 ($5.1M). There is no
  information about Q3 2020.</think><answer>No Answer</answer>
```

**Example 2: Implementing the GRPO reward function in Python**

```
User: Help me implement the abstention-aware reward function for my RL training loop.

Approach:
1. Parse the model output for <think> and <answer> tags.
2. Compute format reward (structural compliance).
3. Compute answer reward (accuracy or correct abstention).
4. Return combined reward.

Output:
```python
import re
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(['rougeL'], use_stemmer=True)

def compute_reward(prediction: str, ground_truth: str) -> float:
    """Abstention-aware reward: R = R_format + R_answer."""
    # Format reward: valid <think>...</think><answer>...</answer> structure
    has_think = bool(re.search(r'<think>.+?</think>', prediction, re.DOTALL))
    has_answer = bool(re.search(r'<answer>.+?</answer>', prediction, re.DOTALL))
    r_format = 0.5 if (has_think and has_answer) else 0.0

    # Extract answer text
    answer_match = re.search(r'<answer>(.*?)</answer>', prediction, re.DOTALL)
    pred_answer = answer_match.group(1).strip() if answer_match else prediction.strip()

    pred_abstains = pred_answer.lower() == "no answer"
    gold_abstains = ground_truth.lower() == "no answer"

    # Answer reward
    if pred_abstains and gold_abstains:
        r_answer = 1.0  # Correct abstention
    elif not pred_abstains and not gold_abstains:
        rouge = scorer.score(ground_truth, pred_answer)['rougeL'].fmeasure
        em = 1.0 if pred_answer.lower() == ground_truth.lower() else 0.0
        r_answer = rouge + em  # Max 2.0 for perfect match
    else:
        r_answer = 0.0  # Hallucination or over-abstention

    return r_format + r_answer
```

def rag_with_abstention(query: str, retriever, llm) -> dict:

## Best Practices

- **Do** include unanswerable examples as 20-30% of your training mix. The paper shows this ratio is critical -- too few and the model never learns to abstain; too many and it over-abstains.
- **Do** use the two-stage pipeline (SFT then RL). SFT alone causes overconfidence. RL alone without SFT initialization struggles to learn the structured output format. The combination is what works.
- **Do** make "No Answer" a first-class output in your reward function, worth full credit (1.0) when correct. If you penalize abstention or give it partial credit, the model learns to always attempt an answer.
- **Do** require explicit reasoning before abstention via the `<think>` block. Forcing the model to articulate *why* it cannot answer improves both abstention accuracy and user trust.
- **Avoid** relying on output probability calibration (e.g., softmax thresholds) as your abstention mechanism. The paper shows this is unreliable for complex reasoning tasks.
- **Avoid** using only implicit information cues (raw context, knowledge graphs) without explicit CoT supervision. The paper finds implicit information provides limited benefit for reasoning with abstention -- explicit step-by-step reasoning is what drives improvement.

## Error Handling

- **Over-abstention (model says "No Answer" too often):** Check your training data balance -- if unanswerable examples dominate, the model learns a shortcut. Also verify your RL reward doesn't inadvertently make abstention the "safe" high-reward option. Add a small penalty (e.g., -0.1) for false positives during RL.
- **Malformed output tags:** If the model produces broken `<think>/<answer>` tags, the format reward (R_format = 0) will drive correction during RL. In production, implement regex fallback parsing and route malformed outputs to a retry or human review.
- **Temporal context extraction failures:** If the temporal filtering step removes all context (over-filtering), fall back to the full context. Log these cases to improve your temporal parser.
- **Reward hacking in RL:** Monitor for models that always output "No Answer" to collect the easy 1.0 reward. Track the abstention rate per epoch -- if it spikes above your training data's unanswerable ratio, increase the KL penalty (beta) to stay closer to the SFT policy.
- **SFT CoT quality issues:** If teacher-generated CoT traces contain hallucinated reasoning steps, the student inherits them. Always filter: only keep traces where the final answer matches ground truth exactly.

## Limitations

- **Requires labeled unanswerable examples.** You need ground truth "No Answer" labels in your training data. For domains where this annotation is expensive or ambiguous (e.g., open-domain QA), the pipeline is harder to apply directly.
- **Binary abstention only.** The method outputs either an answer or "No Answer" -- it does not express degrees of uncertainty (e.g., "I'm 60% confident"). For graded uncertainty, you'd need to extend the reward function.
- **GRPO computational cost.** Sampling G=4 outputs per question during RL training multiplies inference cost by 4x. For very large models or datasets, this may require significant compute.
- **Domain transfer is not guaranteed.** A model trained to abstain on temporal QA may not transfer abstention ability to other domains (medical, legal, etc.) without domain-specific retraining.
- **The "No Answer" token is a convention.** Users and downstream systems must be designed to handle this output. In conversational settings, a raw "No Answer" response may feel jarring without UX adaptation.
