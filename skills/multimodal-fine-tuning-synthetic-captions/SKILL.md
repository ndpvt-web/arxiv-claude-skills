# Multimodal Fine-Tuning with Synthetic Captions

This skill enables Claude to help users bridge the gap between multimodal pre-training and unimodal fine-tuning by generating synthetic image captions using Multimodal Large Language Models (MLLMs) and fine-tuning vision-language models (e.g., CLIP) with a combined standard + supervised contrastive loss. The technique, from Enomoto & Yamaguchi (arXiv:2601.21426), transforms any labeled image classification dataset into a multimodal one, yielding measurable gains especially in few-shot settings (e.g., +3.4% accuracy at 4-shot on 13 benchmarks).

## When to Use

- When the user has a labeled image classification dataset and wants to improve fine-tuning performance on CLIP or similar vision-language models
- When the user is working with few-shot learning scenarios (4-16 samples per class) where standard fine-tuning underperforms
- When the user asks to generate descriptive captions for images using an MLLM like Gemini or GPT-4o
- When the user wants to convert a unimodal image dataset into a multimodal image-text dataset for contrastive learning
- When the user needs a custom inference strategy using class-averaged text embeddings instead of single text templates
- When the user is building a training pipeline around OpenCLIP or similar CLIP implementations and wants to add a supervised contrastive loss term

## Key Technique

**Caption generation via structured prompts.** For each image, three captions are generated by an MLLM (e.g., Gemini 2.5 Flash-Lite at temperature=0.2) using the template: `"To differentiate this [class_name] photo from other [domain] photos, describe its primary [characteristics] characteristics based on the photo in 50 words."` The `[characteristics]` slot takes three values — `visual`, `shape`, and `texture` — producing three complementary captions per image. Each caption is then prepended with `"a photo of a [class_name]."` to anchor it to the class label. The result fits within CLIP's 77-token limit (mean ~60 tokens).

**Combined contrastive loss for fine-tuning.** Standard CLIP fine-tuning (FLYP) uses image-text contrastive loss where each image is paired with its synthetic caption. This paper adds a supervised contrastive term that pulls same-class representations together: `L = (1 - w) * L_std + w * L_sup`, where `L_sup` computes contrastive loss using a class-identity mask (same-class pairs are positives, cross-class pairs are negatives). The weight `w` is optimally set around 0.1-0.2.

**Class-averaged text embedding inference.** At inference time, instead of using a single text template like `"a photo of a [class]"`, all synthetic captions for a given class are individually normalized, averaged, and re-normalized to produce a robust class text embedding. The image embedding is compared against these averaged class embeddings via cosine similarity. This aggregation smooths out individual caption noise and captures richer class semantics.

## Step-by-Step Workflow

1. **Inventory the dataset.** Identify the image classification dataset, its class labels, the domain descriptor (e.g., "flowers", "aircraft", "birds"), and the number of samples per class. Determine if this is a standard or few-shot setting.

2. **Design the three caption prompts.** For each image, construct three prompts by filling the template:
   ```
   To differentiate this {class_name} photo from other {domain} photos,
   describe its primary {characteristic} characteristics based on the photo in 50 words.
   ```
   where `{characteristic}` is one of: `visual`, `shape`, `texture`.

3. **Generate captions with an MLLM.** Send each image + prompt to an MLLM API (Gemini Flash-Lite recommended for cost/quality balance; GPT-4o mini also works). Use temperature=0.2 for consistency. Store results as JSON keyed by image path, with three caption fields per image.

4. **Prepend class context to each caption.** For every generated caption, prepend the string `"a photo of a {class_name}. "` to anchor the caption to the label. Verify the total token count stays under 77 tokens (CLIP's context window).

5. **Merge captions into a unified dataset file.** Combine the three caption JSONs into a single file where each image maps to its three captions. This becomes the training data alongside the original images and labels.

6. **Configure the multimodal fine-tuning objective.** Set up the combined loss: `L = (1 - w) * L_std + w * L_sup`. Start with `w = 0.1` for standard datasets and `w = 0.2` for few-shot settings. `L_std` is standard CLIP image-text contrastive loss. `L_sup` uses a class-identity mask where `M_ij = 1` if `Y_i == Y_j` (excluding self-pairs), applied over the image-image similarity matrix.

7. **Fine-tune the CLIP model.** During each training step, sample a random caption (from the three available) per image. Compute both loss terms over the batch. Use OpenCLIP's training infrastructure with ResNet-50 or ViT-B/32 backbones. Apply standard CLIP fine-tuning hyperparameters (learning rate, batch size, epochs) from the FLYP baseline.

8. **Build class-averaged text embeddings for inference.** After training, encode all synthetic captions through the text encoder. For each class `k`, normalize each caption embedding individually, average them, then re-normalize: `v_Tk = normalize(mean(normalize(v_Cki) for all i))`. This produces one text embedding per class.

9. **Run inference with cosine similarity.** For a test image, encode it with the image encoder, compute cosine similarity against all class-averaged text embeddings, and predict the class with the highest similarity.

10. **Evaluate and tune.** Compare against the FLYP baseline (standard CLIP fine-tuning with text templates). If gains are marginal, try adjusting `w` in [0.05, 0.3]. In few-shot settings, the caption-based approach can outperform fine-tuning even without training (zero-shot with synthetic captions).

## Concrete Examples

**Example 1: Few-shot flower classification with CLIP**

User: "I have a Flowers102 dataset with only 8 images per class. I want to fine-tune CLIP ResNet-50 for better accuracy."

Approach:
1. Set domain = "flowers", enumerate all 102 class names from the dataset metadata
2. For each training image, generate 3 captions using Gemini Flash-Lite:
   - Visual: "To differentiate this sunflower photo from other flowers photos, describe its primary visual characteristics based on the photo in 50 words."
   - Shape: same template with "shape"
   - Texture: same template with "texture"
3. Prepend "a photo of a sunflower." to each caption
4. Fine-tune with `w = 0.2` (higher weight for few-shot) using combined loss
5. Build class-averaged embeddings from all `8 * 3 = 24` captions per class
6. Run inference on test set

Output:

**Example 2: Full-dataset aircraft classification pipeline**

User: "I want to build a complete training pipeline for FGVC Aircraft classification using synthetic captions and CLIP ViT-B/32."

Approach:
1. Set domain = "aircraft", extract variant names (e.g., "Boeing 737-200")
2. Generate captions for all training images (3 per image)
3. Build merged caption JSON:
   ```json
   {
     "train/0001.jpg": {
       "visual": "a photo of a Boeing 737-200. ...",
       "shape": "a photo of a Boeing 737-200. ...",
       "texture": "a photo of a Boeing 737-200. ..."
     }
   }
   ```
4. Fine-tune ViT-B/32 with `w = 0.1` using the combined loss
5. Build class-averaged embeddings for all 100 aircraft variants
6. Evaluate on test split

Output:
```python
# Supervised contrastive loss implementation
def supervised_contrastive_loss(image_features, labels, temperature=0.01):
    similarity = image_features @ image_features.T / temperature
    # Build class-identity mask: M_ij = 1 if labels[i] == labels[j]
    mask = (labels.unsqueeze(0) == labels.unsqueeze(1)).float()
    mask.fill_diagonal_(0)  # Exclude self-pairs
    # Compute loss over positive pairs
    exp_sim = torch.exp(similarity)
    log_prob = similarity - torch.log(exp_sim.sum(dim=1, keepdim=True))
    loss = -(mask * log_prob).sum(dim=1) / mask.sum(dim=1).clamp(min=1)
    return loss.mean()

# Combined objective
loss = (1 - w) * standard_clip_loss(img_emb, txt_emb) + w * supervised_contrastive_loss(img_emb, labels)
```

**Example 3: Class-averaged inference without fine-tuning**

User: "I have pre-generated captions for CUB-200 birds. Can I use them to improve zero-shot CLIP classification without any training?"

Approach:
1. Load all captions grouped by class
2. Encode each caption through CLIP text encoder
3. Normalize, average per class, re-normalize
4. Compare test images against class-averaged embeddings

Output:
```python
import torch
from open_clip import create_model_and_transforms, get_tokenizer

model, _, preprocess = create_model_and_transforms('ViT-B-32', pretrained='openai')
tokenizer = get_tokenizer('ViT-B-32')

# Build class-averaged text embeddings
class_embeddings = {}
for class_name, captions in captions_by_class.items():
    tokens = tokenizer(captions)
    with torch.no_grad():
        embs = model.encode_text(tokens)
        embs = embs / embs.norm(dim=-1, keepdim=True)  # Normalize each
        avg_emb = embs.mean(dim=0)                       # Average
        avg_emb = avg_emb / avg_emb.norm()               # Re-normalize
    class_embeddings[class_name] = avg_emb

# Stack into matrix for inference
class_matrix = torch.stack(list(class_embeddings.values()))

# Classify a test image
image_emb = model.encode_image(preprocess(image).unsqueeze(0))
image_emb = image_emb / image_emb.norm(dim=-1, keepdim=True)
similarities = (image_emb @ class_matrix.T).squeeze()
predicted_class = list(class_embeddings.keys())[similarities.argmax().item()]
```

This zero-shot approach with synthetic captions outperforms standard text-template zero-shot CLIP and can even surpass fine-tuned models at 4-8 shots.

## Best Practices

- **Do:** Use all three caption types (visual, shape, texture) together. Ablations show the combination outperforms any single type by ~0.5-1.5%.
- **Do:** Keep captions under 50 words so the prepended class template stays within CLIP's 77-token window. Specify the word limit explicitly in the prompt.
- **Do:** Set MLLM temperature to 0.2 for caption generation. Higher temperatures produce more creative but less discriminative descriptions.
- **Do:** Use `w` between 0.1 and 0.2 for the supervised contrastive weight. Tune on a validation split — values above 0.3 can collapse representations.
- **Avoid:** Generating captions without the class label in the prompt. The class name is critical for producing discriminative (not generic) descriptions.
- **Avoid:** Using a single text template (e.g., "a photo of a {class}") at inference time when you have synthetic captions available. Class-averaged embeddings from real captions consistently outperform templates.

## Error Handling

- **Captions exceed token limit:** If the MLLM ignores the 50-word constraint, truncate captions at the token level after prepending the class prefix. Check with `len(tokenizer.encode(caption))` and trim to 77 tokens.
- **MLLM refuses or returns empty captions:** Some images may fail (blurry, ambiguous). Fall back to the template `"a photo of a {class_name}."` for that image. Log failures for manual review.
- **Class imbalance in captions:** If some classes have far fewer images (and thus fewer captions), the class-averaged embeddings will be noisier. Consider generating multiple caption sets per image (re-run with temperature=0.4) to increase diversity.
- **Supervised contrastive loss produces NaN:** This happens when a class has only one sample in a batch (no positive pairs). Ensure batch size is large enough that each class appears at least twice, or add a `clamp(min=1)` guard on the denominator.
- **Fine-tuning diverges with high `w`:** Reduce `w` to 0.05 and increase gradually. The supervised term is strong and can dominate if weighted too heavily.

## Limitations

- Requires an MLLM API for caption generation, which adds cost proportional to dataset size. For 50K images with 3 captions each, expect ~150K API calls.
- Designed for and validated on image classification tasks only. Not directly applicable to detection, segmentation, or generation tasks without adaptation.
- Gains diminish as training data increases. The largest improvements are in few-shot (4-16 samples/class). With full datasets, improvements are ~0.5% average.
- CLIP's 77-token context window constrains caption length. Longer, more detailed captions cannot be fully utilized without switching to a model with a larger context (e.g., SigLIP).
- Caption quality depends on the MLLM's visual understanding. Domain-specific or highly specialized images (medical, satellite) may produce lower-quality captions.
